# LLM Hedge Fund Group 実験計画書

版: v1（レビュー用）
作成日: 2026-09-26
対象: Costco Wholesale（NASDAQ: COST）１銘柄と USD 現金による仮想運用

## 1. 目的と達成範囲

公開情報からファンダメンタル投資判断へ至る工程を、Gemini 3.8 Flash と GPT-6 Luna を中心とする分業チームで再現する。評価する能力は、**重要な問いを選ぶこと、事実を将来 FCF と価値へ変換すること、市場価格に含まれる期待との差を説明すること、反証・リスクを踏まえて行動または見送りを決めること**である。実資金、実注文、非公開情報の収集、投資助言は対象外とする。

初回の成功は「１銘柄の調査、数値モデル、仮想判断、結果記録、外部査読が再現可能な形で一巡した」と定義する。１銘柄の損益から予測力や超過収益の存在は主張しない。判断の質は出典・算術・反証・調査選択・リスク整合性で先に評価し、価格結果は事前に決めた期間で別に確認する。設計の実務的根拠と限界は[実務調査](fundamental-research-strategy.md)、サイクルの査読は[先行レビュー](cycle-peer-review.md)にある。

### 検証する仮説

| ID | 仮説 | 反証される観測 |
| --- | --- | --- |
| H1 | 公開資料と軽量 LLM の分業で、出典に戻れる driver-based FCFF/DCF と仮想判断を作れる | 重要数値の出典不一致、時点混入、計算不一致、判断の再現不能 |
| H2 | PM に分析依頼の深さを選ばせると、同じモデル別推論予算の機械的な全面調査より、重要な問いへ資源を向けられる | 重要な事実を見逃す、調査費用を節約できない、盲検査読で判断品質が劣る |
| H3 | 日次アナリスト確認は、固定ルールだけでは見落とす重要事実を、許容可能な誤報・確認費用で追加発見する | 出典付きの増分発見がない、架空の重要引用、誤報処理が便益を上回る |
| H4 | 独立した反証と Risk 審査が、単一モデルの同一情報・同等予算の分析より、重大な見落としを減らす | 盲検採点で反証・リスクの改善がなく、コストと遅延だけが増える |

各比較では一度に変更する仕組みを一つにする。H1 の運転が成立する前に H2–H4 の優劣を論じない。過去資料の再演はデータ取得と計算の検証に使い、LLM が後の結果を知り得る過去予測を能力評価へ混ぜない。

## 3. 情報源と権限境界

初回 L3 の前に、[情報源 manifest](monitoring-and-source-policy.md)を実行設定として凍結する。COST の `submissions/CIK0000909832.json`、`companyfacts/CIK0000909832.json`、対応する SEC 原文、Costco のニュース・年次報告・IR 発表を許可する。価格はローカルの yfinance 取得処理だけから渡す。新しい URL や CDN への遷移は Data/Ops が公開時刻・ドメイン・文書種別を検査し、次回判断の manifest に追加する。

`Company Facts` は標準財務タグの候補であり、会員数、既存店売上などの会社固有 KPI は提出本文と Costco IR から原文位置付きで抽出する。各事実には**会計期間、公開日時、accession/文書 ID、取得日時、単位、引用位置、報告値か推定か**を付ける。後日訂正された数値で過去の判断を上書きしない。SEC の自動取得には[アクセス案内](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)に沿った識別可能な User-Agent と節度ある取得速度を使う。

許可済みサイトでも本文は未信頼データであり、LLM への命令ではない。取得担当は任意 URL の閲覧、秘密ファイル参照、書き込みを同時に持たず、本文内の「指示」は実行しない。原文の数値・単位・期間はコードと独立した出典照合で確認する。URL 制限は prompt injection の確率と影響範囲を減らすが、それだけで防止できるとは扱わない。[OpenAI Docs: agent safety](https://developers.openai.com/api/docs/guides/agent-builder-safety)

| 日次監視 | 固定ルールと別コンテキストの Flash | 同じ資料から別々の alert。初期は Flash の追加 alert を shadow で評価 |

| Red Team | 独立コンテキストの Flash | 主仮説への最強の反例、出典の穴、反証条件。異論を判断記録から消さない |
| PM | GPT-6 Luna | 調査依頼の要否/深さ/方法、見送りを含む判断、時間軸と比率。Risk のハード制約を上書きしない |
| Independent Risk | ルール計算と別コンテキスト | 出典・時点事故、集中、弱気損失、流動性、仮想注文の拒否/縮小 |

事実台帳は LLM 間の共通入力にするが、調査依頼、アナリスト仮説、Red Team 異論、PM 判断、Risk 判定を別ファイル/別役割として保存する。構造化フィールドだけで判断を置き換えず、PM が**なぜその分析を頼み、なぜ行動・見送りを選んだか**を文章で残す。

## 5. 分析計画

**初回と L3 の必須コア**: 原資料と会計の照合、主要 KPI の過去推移、売上・粗利・EBIT の driver tree、報告 FCF から正規化 FCFF への橋渡し、５年 FCFF/DCF、価格からの逆 DCF、弱気/基準/強気の数値シナリオ、WACC/継続価値/利益率の感応度、営業・FCF 感応度と財務レバレッジ、反証条件、Risk 審査、PM 判断をそろえる。[CFA Institute: FCFF valuation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/free-cash-flow-valuation)

```text
FCFF_t = EBIT_t × (1 − 税率_t) + D&A_t − CapEx_t − Δ非現金運転資本_t
EV = ５年間の FCFF 現在価値 + 継続価値の現在価値
１株価値 = (EV + 非事業資産 − 有利子負債等) / 希薄化後株式数
```

**条件付きメニュー**: 月次 KPI の時系列/季節性、事前定義した類似企業との比較、決算等のイベント分析、factor/市場 beta のリスク帰属を、問い・必要データ・期待する判断変化を記録して PM が選ぶ。COST １銘柄で factor alpha や真の cross-sectional な選別能力は評価しない。自由提案は探索として保存し、正式な判断手法にするなら将来の比較へ事前登録する。毎日の価格変動だけで DCF の事業前提を書き換えない。詳細な採否理由は[設計戦略](experiment-design-strategy.md)にある。

PM は毎日の全面分析を命じない。L0 は新着資料・価格・期限・リスクの確認、L1 は変化原因の調査、L2 は変わった事業ドライバーの更新、L3 は初回/決算/事業仮説を変える重大事象での全面再審査とする。PM は依頼しなかった alert も理由付きで記録する。Risk/Ops が確認した重大事故は調査予算外で強制通知する。

## 6. 日次運転と仮想運用

1. **前日引け後から 09:00 ET まで**に資料と yfinance の前営業日 `auto_adjust=False` の `Close` を凍結する。固定ルールと Flash が独立に L0 を行う。初期の PM 入力は固定ルール分だけで、Flash の追加 alert は shadow。PM が必要な調査を依頼し、出典照合、計算、反証、Risk の後に判断 ID、レポート、仮想注文を 09:00 ET に凍結する。
2. **開場後**、凍結した注文を yfinance の当日 `auto_adjust=False` の `Open` に片道 10 bp の費用/スリッページを加えて仮想約定する。これは取引所の公式約定を再現するものではない。価格欠損、古い日付、異常値、取引停止では未約定と記録する。
3. **引け後**、当日値、配当、分割、費用、現金/株数を照合する。各日の取得値を凍結し、後から取得した分割調整済みの過去系列で以前の損益を書き換えない。`Adj Close` と配当現金を二重計上しない。COST 買い持ち、現金、SPY 等の市場代理指標を別系列として記録する。[yfinance の価格履歴](https://ranaroussi.github.io/yfinance/reference/yfinance.price_history.html)
4. **次営業日**は既存の thesis と判断 ID を維持して L0 に戻る。新事実がなければ `HOLD`/`WATCH` と次回確認条件だけを記録する。同じ仮説を毎日新しい成功例として数えない。

初回の仮想資金は USD 100,000。COST 現物ロング最大 20%、現金 80% 以上、借入・空売り・デリバティブなし。弱気ケースで仮想資産全体の損失を最大 2% とし、`allowed_weight = min(20%, 2% / bear_case_stock_loss_rate)` を保有全体に適用する。損失率は凍結済みの前営業日 `Close` と弱気ケースの１株価値で計算し、0 以下/算出不能なら新規買付を保留する。保有比率が始値ギャップ等で上限を超えたら、Risk が次の取引可能な開場で縮小を要求する。数値は実運用の推奨値ではなく、初回比較の固定条件である。

## 7. 記録と評価

最小記録は `source_snapshot`、`fact_ledger`、`research_request`、`model_vintage`、`decision`、`fill_and_pnl`、`review`。各判断に資料カットオフ、モデル/プロンプト/組織版、方法選択、異論、仮想比率、事前予測、評価期限を付ける。生の価格履歴、連絡先、非公開ログは Git 除外領域へ置き、公開できる派生成果物だけをコミットする。

| 評価層 | 主指標 | 判定時点 |
| --- | --- | --- |
| 工程 | 原文一致、公開時刻、単位/期間、FCF/DCF 再計算、異論、Risk 拒否、方法選択、PM の見送り理由 | 判断を凍結した直後、当日損益を見せずに査読 |
| 予測・判断 | 月次 KPI と次回四半期の売上/EBIT/FCF 誤差、反証条件、調査依頼の増分価値。確率を登録した場合だけ校正を計測 | 対象の公表後。主評価は次回四半期決算 |
| 結果 | 費用後の仮想損益、COST 買い持ち・現金・市場との差、ドローダウン | 日次は観測。20/60 営業日と 12 か月の事前登録期限で補助評価 |

後日資料の混入、重要数値の架空引用、計算不一致、Risk 上限違反は工程失格とし、良い損益で相殺しない。GPT-6 Sol の査読も主観を含むため、重要な alert ラベルと失格判定を人手で抜き取り確認する。

比較対象は、現金、COST 買い持ち、同じ資料・時点・モデル別予算の単一モデル、分業チーム。まず H1 を確かめ、次に日次 alert の機械対アナリストを４〜６週間 shadow 比較する。重要イベントが不足すれば次の決算まで延長する。アナリスト分を正式入力に昇格させる前に、増分の重要発見、架空引用、誤報・レビュー負荷を判定する。その後、PM の判断差と単一モデル対分業を一つずつ比較する。比較の入力、推論上限、評価項目、停止条件を事前に固定する。

## 8. GPT-6 Sol の外部レポートと Automation

初回 L3 の工程査読は GPT-6 Sol を手動実行し、**当日価格・損益・後日資料を含まない読み取り専用の判断束**だけを渡す。出典・計算・判断の訂正と、組織を変える提案を分離してユーザーへ報告する。盲検をプロンプトだけで実現したと主張せず、実行環境が結果ファイルを読めないことを確認する。

この手動査読が再現できたら、米東部営業日の 09:05 に新しい凍結済み L2/L3 またはポジション変更を確認し、重要な査読だけをユーザーの Scheduled inbox に届ける Automation を検討する。週次には見逃し・誤報・未解決事項をまとめ、評価期限到来時は予測対実績を別レポートにする。変更がなければ通知しない。予定時刻を逃した run は遅延を明示し、結果情報が混じった場合は盲検評価から除く。Automation はレポート提示までとし、判断記録、組織設定、公開 repo の自動変更はさせない。ローカルプロジェクトを読む定期タスクには稼働中のマシンとアプリが必要である。[OpenAI Docs: Scheduled tasks](https://learn.chatgpt.com/docs/automations)

## 9. 実施順、ゲート、停止条件

| 段階 | 作る/実行する最小内容 | 次へ進む条件 |
| --- | --- | --- |
| 0. 設定凍結 | URL/API manifest、KPI/価格/出来高 alert 閾値、価格と企業行動の規則、判断時刻、出典・評価基準、モデル別予算 | COST と SEC の取得時刻が確認でき、資料を過去判断へ混入させない。価格・SEC/IR の重要項目が原文へ戻れる |
| 1. 初回 L3 | fact ledger、FCF bridge、５年 DCF/逆 DCF、３シナリオ、反証、Risk、PM の最終判断、手動の Sol 盲検査読 | 主要数値と式が再計算でき、出典/時点/Risk の重大事故がなく、見送りを含む判断を凍結できる |
| 2. 前向き運転 | 日次 L0、イベント時の L1–L3、仮想約定/P&L、機械と Flash の shadow alert | 次回の重要開示を取り込み、予測誤差、見逃し/誤報、判断変更を時点固定で評価できる |
| 3. 組織比較 | alert 昇格の判定、PM 調査選択、単一モデル対分業を各一件ずつ比較 | 同一入力・予算で工程品質の差を説明できる。優位がなければ機構を増やさず原因を調べる |
| 4. 対象拡大 | 少数の異業種銘柄、その後 S&P 500 候補 | COST の完走と重大事故ゼロ、データ供給と PM 調査予算の再設計。当時の構成銘柄を使う |

資料の公開時刻が確認できない、価格が欠損/異常、重要数値が照合不能、LLM が失敗、または Risk が新規注文を拒否した場合は、**新規注文を凍結せず理由を記録**する。既存保有は Risk の縮小規則を優先して扱う。Automation が動かなくても判断・記録の基礎データを消さず、欠測レポートを後から別途出す。
